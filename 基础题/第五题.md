[ 是测试命令，相当于判断条件

-n 意思是：字符串非空，长度大于 0

所以用[ -n "$pid" ] || return 1表示 $pid 为空，就 return 1

/proc 是 Linux 里存放进程信息的目录。每个正在运行的进程，都会有一个 /proc/进程号/ 目录。/proc/$pid/stat 是这个进程的状态文件。-r 意思是：这个文件存在，并且可读

所以用这个,检查进程信息还在不可读不,[ -r "/proc/$pid/stat" ] || return 1

$( ... ):命令替换,它会先运行里面的命令，然后把命令打印到屏幕上的内容，抓回来，赋值给 st

/proc 是 Linux 的一个特殊目录,/proc/$pid/stat,每个正在运行的进程，在里面都有一个以 PID 命名的文件夹.如这个 stat 文件里记录了这个进程的状态信息,它大概长这样，一整行：1234 (slow-worker) S 1 1234 1234 0 -1 4194304 ...

awk 是一个专门处理文本的工具,awk '{print $3}'的意思是：打印第 3 列.所以大概会输出S或R或Z或T或X这样的进程状态.

| 状态 | 含义 | 特点 |
|---|---|---|
| R | Running / Runnable | 正在运行，或在就绪队列等 CPU |
| S | Interruptible sleep | 可中断睡眠，等待事件，能被信号唤醒 |
| D | Uninterruptible sleep | 不可中断睡眠，通常等磁盘 I/O，很难 kill |
| T | Stopped / Traced | 被暂停，比如按了 Ctrl+Z 或被 gdb 调试 |
| Z | Zombie | 已终止，但父进程没调用 `wait()` 回收 |
| t | Tracing stop | 被调试器跟踪暂停 |
| X | Dead | 彻底死亡，几乎看不到 |

2>/dev/null“错误输出”重定向扔掉.
1 是标准输出，正常内容
2 是标准错误，报错内容
/dev/null 是一个黑洞，写进去就消失

所以用 st=$(awk '{print $3}' "/proc/$pid/stat" 2>/dev/null) ,读 /proc/$pid/stat 这个文件,用 awk 取第 3 列,把第 3 列的内容保存到变量 st,不要报错信息.

如果 st 等于 Z，说明是僵尸进程，返回失败
```bash
[ "$st" = "Z" ] && return 1
```

grep -q 是什么？q 意思是 quiet，安静模式。找到：返回 0，不打印任何东西。找不到：返回 1，也不打印任何东西。我们只关心找没找到，不关心它打印什么，所以用 -q

-- 表示“后面的东西不是选项，是普通参数”,防止 $NAME 刚好以 - 开头，被 grep 当成选项

所以用这个tr '\0' ' ' < "/proc/$pid/cmdline" 2>/dev/null | grep -q -- "$NAME"来把这个进程的启动命令读出来，把 \0 换成空格，然后检查里面有没有 slow-worker 这个名字.

```bash
worker_alive() {
    pid=$1
    [ -n "$pid" ] || return 1
    [ -r "/proc/$pid/stat" ] || return 1
    st=$(awk '{print $3}' "/proc/$pid/stat" 2>/dev/null)
    [ "$st" = "Z" ] && return 1
    tr '\0' ' ' < "/proc/$pid/cmdline" 2>/dev/null | grep -q -- "$NAME"
}
```

running_pid >/dev/null 2>&1的意思是运行 running_pid，正常输出和错误输出都丢掉.此时如果worker在跑 退出码为0,worker没在跑,退出码为 1

为什么要有mkdir -p "$WORK_DIR" 2>/dev/null呢?WORK_DIR=${WORK_DIR:-/workspace}不是已经确认有WORK_DIR了么?WORK_DIR只是存了这个一个地址,不代表这个地址真的一定已经对应一个文件夹,所以要保守一点mkdir -p

为什么要rm -f "$PIDFILE"呢?跑到这条说明此时已经确认没有那样的PID或者是僵尸,为了保证：启动前 PID 文件是干净的。万一新 worker 启动失败，不会留下旧的假 PID。 后面 read_pid 读的时候，不会读到过期 PID.另外 -f 可以让文件不存在的情况不报错，直接成功

用 export WORK_DIR 配置一下文件,因为WORK_DIR 只是 manage.sh 这个 bash 进程里的普通变量.slow-worker 是它启动的子进程，默认看不到这个变量.所以要 export WORK_DIR，让 slow-worker 也能看到，知道往哪写日志

cd "$WORK_DIR" 2>/dev/null , 为什么cd一下都要扔掉错误信息?因为这个脚本是给别人用的，start 应该安安静静地成功，不要屏幕上冒一堆红字

0	标准输入	命令从哪读数据，默认是键盘
1	标准输出	命令正常打印到哪，默认是屏幕
2	标准错误	命令报错打印到哪，默认也是屏幕

2>&1 的作用是将标准错误输出（stderr）重定向到标准输出（stdout）,这里的 & 是为了告诉系统，后面的 1 是一个文件描述符，而不是一个文件名为 "1" 的文件

command > /dev/null 2>&1 这句的意思是:标准输出丢到黑洞,标准错误也去标准输出去的地方，也就是也丢到黑洞.总之就是,正常输出和错误输出都丢掉

nohup	不受终端关闭影响
"$WORKER"	要启动的程序
</dev/null	输入来自黑洞，没有输入
>>/dev/null	正常输出丢到黑洞
2>&1	错误输出也丢到黑洞
&	后台运行

用 nohup 运行 $WORKER 这个程序，让它忽略终端挂断信号 SIGHUP,把标准输入（文件描述符 0）重定向为 /dev/null,把标准输出（文件描述符 1）以追加方式重定向到 /dev/null,丢弃错误输出.其中 & 表示放到后台运行
```bash
nohup "$WORKER" </dev/null >>/dev/null 2>&1 &
```

为什么要把标准输入（文件描述符 0）重定向为 /dev/null呢?
让后台进程不应该再等着从终端读输入，否则它可能会“卡住”

最后一个进程的PID用PIDFILE存起来

所以这样做.cmd_start的作用是:如果已经在跑(从前面running_pid的return得到的0或1知道有没有在跑),就什么都不做直接返回成功，没在跑才真正 fork 一个后台进程，并把它的 PID 写进 pidfile
```bash
cmd_start() {
    if running_pid >/dev/null 2>&1; then return 0; fi   
    mkdir -p "$WORK_DIR" 2>/dev/null
    rm -f "$PIDFILE"
    export WORK_DIR
    cd "$WORK_DIR" 2>/dev/null
    nohup "$WORKER" </dev/null >>/dev/null 2>&1 &
    echo $! > "$PIDFILE"
    return 0
}
```

running_pid 成功时把活着的 PID 打印到 stdout 并返回 0  

开一个命令组，把大括号里多条命令的 stdout 合并成一个流，后面统一重定向到同一个文件。比每条命令各自 >> 追加更干净，只打开/关闭一次文件

第一行写 PID=12345 这种标识行，方便一眼看到报告对应哪个进程。用 printf 而不是 echo 是为了格式可控、不会把 -n 之类当选项

用 ps 取该进程的快照信息，-p 指定 PID，-o 定制列：
pid：进程号
ppid：父进程号（看是谁起的它）
user：运行用户
stat：状态（S 睡眠、R 运行、Z 僵尸、D 不可中断等）
etime：已运行时长（[[dd-]hh:]mm:ss）
time：累计 CPU 时间
args：完整命令行

用 top 取该进程的瞬时资源占用：
-b：批处理模式，输出到 stdout 而非交互式界面
-n 1：只刷一帧就退出
-p "$pid"：只监控这一个进程

ps -o etime,time	从启动到现在的累计值（跑了多久、总共用了多少 CPU）

top -b -n 1	这一瞬间的快照（此刻占多少 CPU/内存）

```bash
cmd_report() {
    pid=$(running_pid) || return 1
    {
        printf 'PID=%s\n' "$pid"
        ps -o pid,ppid,user,stat,etime,time,args -p "$pid"
        top -b -n 1 -p "$pid"
    } > "$WORK_DIR/resource.txt"
    return 0
}
```

pid=$(running_pid) || { rm -f "$PIDFILE"; return 0; }这一句是什么意思
先探活。如果 worker 真在跑，running_pid 返回 0、pid 拿到 PID，|| 右边不触发，继续往下杀；如果已经不在跑了（进程死了 / pidfile 不存在 / 是僵尸），就进右边的大括号组：顺手把残留的 pidfile 清掉（因为终态就是“没在跑”，留着只会误导下次 status），然后直接 return 0。注意这里返回 0 而不是 1——对 stop 来说，“没在跑”就是理想结果，不算失败。这和 cmd_report 里同样失败却 return 1 是有意区分的：report 失败是“没法干活”，stop 失败是“活已经干完了”。

kill,作用是给指定进程发信号，不是"杀死"

-TERM
指定信号种类，等价于 -15，即 SIGTERM。这是"请求终止"信号，进程可以捕获它做收尾工作（关数据库连接、刷日志、删临时文件）。对比一下：

    SIGTERM (15)：礼貌请退，可被捕获、可忽略。
    SIGKILL (9)：强杀，内核直接回收，进程来不及做任何清理，无法捕获。
    SIGINT (2)：Ctrl+C 那个，交互式中断。

这里选 TERM 是因为 worker 是后台服务，应该给它机会优雅退出。

"$pid",目标 PID。加双引号是防御性写法：万一 $pid 为空，展开成 kill -TERM ""，kill 会报错

worker_alive "$pid" || break , 这里worker_alive  return 1的时候就退出

-lt：less than，小于

sleep 0.1而不是sleep 1可以让响应更快,用户体验更流畅

总的脚本代码是
```bash
cat > /workspace/manage.sh << 'MANAGE_EOF'
#!/bin/bash

WORKER=${WORKER:-/opt/recruitment/bin/slow-worker}
WORK_DIR=${WORK_DIR:-/workspace}
PIDFILE="$WORK_DIR/worker.pid"
NAME=$(basename "$WORKER")

usage() { printf 'usage: manage.sh start|status|report|stop\n'; }

# 这个 PID 是不是"活着、且确实是我们那个 worker"（僵尸不算）
worker_alive() {
    pid=$1
    [ -n "$pid" ] || return 1
    [ -r "/proc/$pid/stat" ] || return 1
    st=$(awk '{print $3}' "/proc/$pid/stat" 2>/dev/null)
    [ "$st" = "Z" ] && return 1
    tr '\0' ' ' < "/proc/$pid/cmdline" 2>/dev/null | grep -q -- "$NAME"
}

# 从 pidfile 取纯数字
read_pid() {
    [ -f "$PIDFILE" ] || return 1
    p=$(tr -dc '0-9' < "$PIDFILE" 2>/dev/null)
    [ -n "$p" ] || return 1
    printf '%s' "$p"
}

# 输出"确实在跑的 worker"的 PID；否则返回 1
running_pid() {
    p=$(read_pid) || return 1
    worker_alive "$p" || return 1
    printf '%s' "$p"
}

cmd_start() {
    if running_pid >/dev/null 2>&1; then return 0; fi   # 已在跑 → 不重复启动
    mkdir -p "$WORK_DIR" 2>/dev/null
    rm -f "$PIDFILE"
    export WORK_DIR
    cd "$WORK_DIR" 2>/dev/null
    nohup "$WORKER" </dev/null >>/dev/null 2>&1 &
    echo $! > "$PIDFILE"
    return 0
}

cmd_status() {
    if running_pid >/dev/null 2>&1; then echo running; return 0; fi
    echo stopped
    return 1
}

cmd_report() {
    pid=$(running_pid) || return 1
    {
        printf 'PID=%s\n' "$pid"
        ps -o pid,ppid,user,stat,etime,time,args -p "$pid"
        top -b -n 1 -p "$pid"
    } > "$WORK_DIR/resource.txt"
    return 0
}

cmd_stop() {
    pid=$(running_pid) || { rm -f "$PIDFILE"; return 0; }   # 没在跑也算成功
    kill -TERM "$pid" 2>/dev/null
    i=0
    while [ "$i" -lt 100 ]; do        # 等它"真正退出"，不只是发了信号
        worker_alive "$pid" || break
        sleep 0.1
        i=$((i + 1))
    done
    rm -f "$PIDFILE"
    return 0
}

case "${1:-}" in
    start)  cmd_start  ;;
    status) cmd_status ;;
    report) cmd_report ;;
    stop)   cmd_stop   ;;
    *)      usage; exit 64 ;;
esac
exit $?
MANAGE_EOF
```
