写help,printf 是格式化输出命令（比 echo 更可控、跨平台一致）,\n 是换行符(末尾加换行，避免提示和下一行命令连在一起)
```bash
usage() { printf 'usage: route.sh MODE ITEM  (MODE: ok|retry|fatal, ITEM: 1-32 alnum)\n'; }
```

检查传入参数是不是2,退出64.
```bash
if [ "$#" -ne 2 ]; then usage; exit 64; fi
```

把传入的参数给变量mode和item,方便后面记
```bash
mode=$1; item=$2
```

case拿一个值，去和好几种情况挨个比对,就是 "多选一的 if"
esac,类似 if...fi,有 case 就必须有 esac 收尾，就像有 if 就必须有 fi

case "$mode" in 意思是：拿 $mode 这个值，和下面这些情况比一比
case格式:
```bash
case 要检查的东西 in
    情况1) 做什么 ;;
    情况2) 做什么 ;;
esac
```

) 是用来结束"情况"的，表示"左边这些值是这一种情况"

这里的|类似c的逻辑或
```bash
ok|retry|fatal)
```

*,通配符，代表"任何东西"
*) 就是 "其它所有情况"，相当于 if 里的 else

;; 表示"这一种情况到此结束",像 C 里 switch 语句的 break;,是case里面的句号

所以,先检查mode是不是ok,retry,fatal里面的一种,不是就退出64
```bash
case "$mode" in ok|retry|fatal) ;; *) usage; exit 64 ;; esac
```


```bash
case "$item" in ''|*[!A-Za-z0-9]*) usage; exit 64 ;; esac
```

* 的"匹配任意字符"能力，只在两种场景生效：

    case 语句里

    文件名匹配（glob）里

位置不同含义不同:
单独的 * ：任意多个字符（包括 0 个）
在开头 —— *abc : 前面随便啥，结尾必须是 abc
在结尾 —— abc*: 开头必须是 abc，后面随便
在两边 —— *abc*: 只要里面有 abc 就行，前后不管
在中间 —— a*b: a 开头，b 结尾，中间随便
注意重点:引号里的 * 不是通配符，是普通字符.加引号后 * 就"失效"了

所以,如果不是空字符和有非1–32 个英文字母或数字,就继续.
```bash
case "$item" in ''|*[!A-Za-z0-9]*) usage; exit 64 ;; esac
```

#放在变量名前面时，表示“长度”
${}	变量扩展/变量引用
-gt  greater than，大于

给变量加 ""，是为了：

    变量为空时不让 [ ] 语法崩

    变量里有空格时不被拆成好几块

记不住就记：放进 [ ] 的变量，一律加双引号

所以这样来让item大于32就退出64
```bash
if [ "${#item}" -gt 32 ]; then usage; exit 64; fi
```

$0 就是当前脚本自己的名字/路径

readlink -f 的作用：把路径变成完整的绝对路径

dirname ：去掉最后的文件名，只留文件夹

拼上 /job.env,中间那个 / 是手动加的，拼起来就是：/home/user/job.env
"/home/user" /job.env

config(配置),用config接收
```bash
config="/home/user/job.env"
```

$(命令) 叫命令替换：把命令执行的结果取出来，当字符串用

```bash
dirname "$(readlink -f "$0")"
#       ↑                ↑
#     外层引号        内层引号
```

    内层 "$0"：防止脚本路径带空格时崩。

    外层 "$(...)"：把整个命令结果锁成一个整体，防止结果带空格被拆开

所以,这样做,不用把地址写死,到时候地址改了,就不用改上百条代码
```bash
config="$(dirname "$(readlink -f "$0")")/job.env"
```

case 里的 |：匹配多个模式，相当于“模式 A 或模式 B”。
命令间的 ||：控制命令是否执行，相当于“前面失败就执行后面”。
命令间的 |：管道，传递输出。

[ -f ... ] : 其中的 -f 是文件判断符，意思是"是不是一个文件且存在

所以这条,配置文件在吗？不在就用默认的
```bash
[ -f "$config" ] || config=/workspace/job.env 
```

不能直接丢掉PATH原来的值;在这里:是分隔符,在前面的会被先找,没找到再用PATH.PATH 是"去哪找命令"的清单。task-probe 放在一个不在清单里的目录，系统找不到它。这句就是把那个目录加到清单最前面，系统才能找到 task-probe.
```bash
PATH="${TASK_TOOL_DIR}:${PATH}"
```

脚本启动后,想让脚本启用的子进程也可以看到PATH,所以用export这样干. (其实PATH早就是环境变量了,赋值后自动带 export 属性，export 只是保险)
```bash
export PATH
```

调用工具，立刻保存退出码
```bash
output=$(task-probe "$mode" "$item")
status=$?
```

这些数字都是约定好的，不是随便定的：
数字	常见含义
0	成功
11	资源暂时不可用（类似"再试一次"）
23	数据错误/被拒绝
75	EX_TEMPFAIL（临时失败，可重试）
65	EX_DATAERR（数据格式错误）

根据task-probe的退出码来写最终的退出码
```bash
case "$status" in
    0)  result=$output;          rc=0  ;;
    11)  result="retry:$item";    rc=75 ;;
    23)  result="rejected:$item"; rc=65 ;;
    *)  exit "$status" ;;
esac
```

按照题目要求,准备退出的内容,用$ROUTE_RESULT存起来
```bash
printf '%s\n' "$result" > "$ROUTE_RESULT"
```

设置rc作为退出码
```bash
exit "$rc"
```
